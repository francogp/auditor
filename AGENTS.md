# Purpose

Core standalone static analysis and architecture verification engine (`@francogp/auditor`). Provides the BaseAuditor framework, streaming runner, UnifiedTheme Box-Drawing reporting, CLI tools, AST context caching, and 42 built-in generic suites (including `validate_html_validate` for strict HTML5 standards, `validate_stylelint` for stylesheet hygiene, `validate_eslint_config` for domain type compliance, and `validate_similar_code` for vector semantic duplication).

## Ownership

Architecture & Tooling Engineers.

## Local Contracts

- **Domain Agnostic**: Zero coupling to utility billing or specific host business domains.
- **Absolute Prohibition on Backward-Compatible Code & Loud Failure Mandate**: Writing backward-compatible shims, deprecated alias suites, legacy fallback wrappers, or dual-execution adapter code across `@francogp/auditor` is STRICTLY PROHIBITED. The framework prioritizes clean, uncompromised modern architecture over legacy tolerance. Outdated consumers, legacy configurations, and unmigrated sub-auditor calls MUST fail loudly with immediate, explicit, and blocking errors (`throw new Error(...)` or exit code 1) forcing consumers to upgrade to canonical standards. Maintaining duplicate suites or runtime compatibility bridges that introduce bloat, duplicate findings, or maintenance hazards is completely eradicated.
- **Node.js 26+ Native**: Executes under `--permission` model without external runtimes.
- **Strict Node.js 26+ Native Standard Library Mandate & Absolute Ban on Fragile Homebrew Helpers**: All path resolution, path containment checks, filesystem operations, URL parsing, and runtime utilities across `@francogp/auditor` and all sub-auditors MUST use Node.js native standard library modules (`node:path`, `node:fs`, `node:url`, `node:util`, `node:crypto`) exclusively. Inventing fragile homebrew regexes to sanitize paths (e.g. stripping valid characters via regexes), parse URLs, or extract HTML/template attributes is strictly prohibited. Path containment (CWE-22) must be validated strictly via `path.resolve()` + `path.relative()` checking for `startsWith('..')` or `isAbsolute()`. Web and markup validation must rely on living specification engines (`html-validate`) or robust parsers, never handcrafted regular expressions.
- **FrancoGP Namespace Mandate (`@francogp/*`)**: All generic packages and standalone tooling extracted across Franco's personal projects MUST use the `@francogp` namespace (`@francogp/auditor`), representing the author's handle (Franco Gastón Pellegrini). Using `@antigravity` or arbitrary vendor names is strictly prohibited.
- **Single Source of Truth Configuration**: Dynamically loads paths, persistence settings, and host extensions via `audit.config.ts`.
- **Mandatory GSAP UI Animation Governance (`manualAnimations`, `manualTimersFrontend`, `noLayoutAnimationInGsap`)**: GSAP animation enforcement rules are strictly mandatory and non-downgradable (`severity: 'error'`). `manualTimersFrontend` scopes timer checks strictly to UI components and views (`.vue` or within `componentsRoots`/`viewsRoots`), allowing legitimate Node.js CLI and runner timeouts while barring uncoordinated timers in UI workflows. `gsapSleep` and `delayedCall` are universal framework standards for UI delays and animation timing across all projects, scaling deterministically with `timeScale(100)` in automated tests. Additional custom timer functions can be registered dynamically via `config.animation.customTimerFunctions`.
- **Zero Bespoke Host Logic in Core Framework**: Sub-auditors in `@francogp/auditor` MUST NOT contain bespoke rules or styling constraints tailored exclusively to a single host application (e.g. 360° button borders or canvas game loops). Host projects must extract and register bespoke rules as extension sub-auditors in `scripts/auditors/` using reference blueprints from `.agents/skills/auditor/references/extensions/`.
- **Pure Configuration-Driven Resolution**: Core analyzers and sub-auditors MUST NEVER hardcode fallback candidate file names (e.g. `'visuals.ts'`, `'zLayers.ts'`, `'layers.ts'`). All file paths, migration directories (`config.paths.migrationsDir`), CLI roots (`config.paths.cliRoots`), and ignore globs (`config.paths.ignoreGlobs`) must resolve strictly and dynamically from `audit.config.ts`.
- **Dynamic SSoT Path Discovery & Subsystem Gating**: All architectural checks (database paths, stores, styles, test file sizes) must resolve dynamically from `audit.config.ts`. Any non-applicable subsystem in tool packages or non-web packages must be explicitly deactivated (`domain.enabled: false`, `persistence.engine: 'none'`).
- **Hermetic Testing & Negative Verification**: Framework unit tests reside in `tests/` and execute in Vitest `node` environment. Every test suite MUST include clean path verification (`errors).toBe(0)` and `status).toBe('passed')`). `validate_auditor_tests` enforces `missing-clean-auditor-test` as `severity: 'error'` across all core suites and host extensions.
- **Zero Live Repository Scanning in Unit Tests**: Sub-auditor unit tests MUST NEVER execute full workspace scans (`auditor.execute()`) directly on `process.cwd()` without isolation. They MUST test individual snippets with `testScanFile` followed by `await auditor.finishAudit()`, or instantiate the auditor with a temporary sandbox directory via `projectRoot`. Scanning the live host repository in unit tests leaks application code defects into testing infrastructure.
- **Fallow 100% Error Severity & Zero-Warning Mandate**: All Fallow findings (including large functions >60 LOC, refactoring targets, cyclomatic/cognitive complexity, code duplication, CWE security candidates, unused files/exports/members/types, and unresolved imports) MUST be mapped strictly to `severity: 'error'`. Downgrading any Fallow finding to `warning` is strictly prohibited across the entire auditor engine and its unit test suites.
- **Fallow Refactoring Targets & Workspace Diagnostics**: Configurable through `config.fallow.enforceTargets` (`severity: 'error'`) and `config.fallow.maxTargetPriority` (`'critical'`, `'high'`, `'all'`). Workspace diagnostics are validated under `validate_fallow_config`.
- **Vector Semantic Duplication, Hardware Execution & Cache Architecture**: `validate_similar_code` verifies semantic duplicates via Fallow embeddings (`jina-embeddings-v2-base-code`) with surgical sensitivity (`threshold: 0.95`, `ignoreSameFile: true`). Execution runs strictly on **Candle CPU** (CPU-only, no GPU/CUDA support) accelerated via `--threads ${os.availableParallelism()}`. Vector embeddings and model weights are persisted in the OS user cache directory (`%LOCALAPPDATA%\fallow\similar-code` on Windows, `~/.cache/fallow/similar-code` on Linux). Subdirectories `models/` and `vectors/` MUST be pre-created by the auditor (`ensureFallowCacheDirs`) and setup scripts (`setup-linux.sh`, `setup-windows.ps1`) to avoid Windows `os error 3`, reducing run times from >230s down to ~2s. It runs in the general auditor (`npm run audit`) and native CLI (`npm run audit:similar`), and is strictly bypassed in fast presets (`preset=lint`, `preset=md`, `audit:for-commit`).
- **Strict Local Execution Mandate & Absolute Prohibition of Bypassing Vector Duplication in Local/Development**: AI agents and developers MUST NEVER set `AUDITOR_SKIP_SIMILAR_CODE_VECTOR_ANALYSIS=1` or `AUDIT_SKIP_SIMILAR=1` during local development, interactive agent turns, local builds, or developer test runs. Vector semantic duplication executes locally on Candle CPU in ~2s leveraging disk cache. There is NO CLI flag to skip similar code. Bypassing vector analysis via the environment variable `AUDITOR_SKIP_SIMILAR_CODE_VECTOR_ANALYSIS=1` (or `AUDIT_SKIP_SIMILAR=1`) is STRICTLY AND EXCLUSIVELY reserved for specifically defined, headless remote deployment workflows (e.g. GitHub Pages deploy workflows or resource-constrained external CI containers). If uninitialized and not skipped, the local model is automatically downloaded via `fallow similar-code setup --local --yes`. If automatic setup fails, the auditor displays a prominent Box-Drawing warning banner with the manual installation command (`npx fallow similar-code setup --local --yes`), recording `fallow-similar-code-failed` as a non-fatal warning (`severity: 'warning'`) so other suites remain unblocked. Specification: [similar-code-analysis.md](https://git.mitgai.net/fallow-rs/fallow/blob/main/docs/similar-code-analysis.md).
- **Static Security Single Source of Truth**: Security vulnerability scanning across all host repositories and auditor packages is governed exclusively by **Fallow** (`fallow security`). ESLint MUST NOT be configured with security plugins (`eslint-plugin-security`), avoiding duplicate reporting and false positives on AST or filesystem operations.
- **Consolidated Box-Drawing Table Total Row Mandate**: All multi-category terminal tables rendering finding breakdowns (in `unifiedTheme.renderBoxTable`, `audit_full.ts`, `report_findings.ts`) MUST append a formatted `TOTAL CONSOLIDADO` footer row with a separating horizontal line (`├───┼───┤`), clearly displaying the sum of errors and warnings across all rows to prevent visual summation discrepancies and terminal cognitive friction.
- **Sub-Auditor Modular Description & Badge Constraint**: Every sub-auditor MUST declare mandatory `packageName: string` and pure Spanish `ruleDescriptions: Record<TRuleId, string>` covering 100% of declared rules without hardcoded package prefixes. Composed descriptions (`${packageName}: ${ruleDescription}`) MUST remain `<= 50` characters (`MAX_AUDITOR_DESCRIPTION_LENGTH = 50`) and contain zero newlines; exceeding 50 characters throws an explicit runtime `Error` during instantiation. Silent prefix stripping or text truncation is strictly forbidden. Live progress badges are clean and silent when 0 findings, and formatted as `(🐛 ${count})` when findings > 0.
- **Capability-Driven Auto-Coordination Mandate (`AuditorCapabilities`) & Zero-Boilerplate Defaults**: Sub-auditors declare execution capabilities (`fix`, `lint`, `md`, `ast`, `changedSince`, `heavy`, `requiresBuild`) cleanly via `AuditorOptions.capabilities?: Partial<AuditorCapabilities>`. `BaseAuditor` guarantees immutable defaults (`DEFAULT_AUDITOR_CAPABILITIES` with all flags set to `false`). Sub-auditors only declare active capabilities where they differ from defaults (e.g. `capabilities: { lint: true, fix: true }`). Repeating redundant `false` flags across constructors is strictly forbidden. When `auditor fix` or `auditor --fix` is invoked, the master orchestrator (`audit_full.ts`) and scanner (`auditScanner.ts`) dynamically isolate and run only auto-repair suites (`capabilities.fix === true`) under the dedicated `[ 🛠️ MODO REPARACIÓN AUTOMÁTICA ]` terminal interface. Fast presets (`preset=lint`, `preset=md`) dynamically select suites matching `capabilities.lint === true` or `capabilities.md === true`. Heavy suites (`capabilities.heavy === true`) are automatically bypassed in fast presets. Suites requiring compiled artifacts (`capabilities.requiresBuild === true`) are dynamically routed to `audit:build` (`preset=build` / `auditor-build`) and executed post-build against `dist/`, excluded from default pre-build source `audit`.
- **Demo & Sandbox Roots Complexity Exemption (`paths.demoRoots`)**: UI demo galleries, test harnesses, and experimental sandboxes configured under `config.paths.demoRoots` (e.g. `'ui-demo'`) are exempted from function complexity, LOC, and magic number alerts in `audit_project.ts` and `audit_rules.ts`, while retaining 100% of domain type checks and dead code analysis.
- **Strict ESLint Flat Config & Zero-Tolerance Type Integrity (`eslint.config.js`)**: All projects governed by `@francogp/auditor` MUST maintain a root `eslint.config.js` enforcing `@typescript-eslint/no-explicit-any: 'error'`, `@typescript-eslint/no-restricted-syntax` banning `TSUnknownKeyword` (`as unknown as`) and legacy `new Date()` / `Date.now()`. `forbiddenTypeCasts` in `audit_rules.ts` enforces static eradication of `as any`, `: any`, `<any>`, and `as unknown as` with zero tolerance under `/domain-type-first`.
- **Automated ESLint Configuration Governance (`validate_eslint_config`)**: `validate_eslint_config` verifies that ESLint flat configuration is present and strictly enforces `@typescript-eslint/no-explicit-any`, double cast prohibition, `@typescript-eslint/ban-ts-comment` error status, and legacy `Date` restriction in favor of Temporal API.
- **Official Stylelint Engine & Pure Execution (`validate_stylelint`)**: All stylesheet and component style hygiene, duplicate class rules, similar selectors, empty blocks, property order, and SCSS syntax are analyzed strictly through the official Stylelint engine with Vue SFC and SCSS support (`stylelint`, `stylelint-scss`, `stylelint-order`). - **Pure Configuration-Driven Bundle Budgets (`validate_bundle_budget`)**: The bundle budget auditor (`validate_bundle_budget`) MUST NOT hardcode fallback chunk size thresholds (`MAX_CLIENT_CHUNK_WARN_BYTES`, `MAX_CLIENT_CHUNK_ERROR_BYTES`) or ad-hoc file budgets. All budgets and byte limits (`maxClientChunkErrorBytes`, `maxClientChunkWarnBytes`, `budgets`) must resolve strictly and dynamically from `audit.config.ts`. - **Universal Standard Build Script Mandate (`npm run build`)**: The `@francogp/auditor` engine and consumer projects MUST strictly use the universal standard npm convention `npm run build` (`"build": "npm run audit && tsc -p tsconfig.build.json && node --experimental-strip-types src/cli/make_executable.ts && npm run audit:build"` in package distributions) for compiling and emitting distribution artifacts into `dist/`. Each sub-auditor declares its required gitignore entries via `AuditorOptions.gitIgnoreEntries?: readonly GitIgnoreRequirement[]`. `BaseAuditor` dynamically registers them into `GitIgnoreRegistry`. `ValidateAuditConfigAuditor` dynamically collects requirements from all discovered modules and user extensions, verifying `.gitignore` coverage and providing auto-repair (`--fix`).
- **Mandatory Pre-Compilation Audit Chaining Across All Projects (`validate_audit_config`)**: Across ALL projects governed by `@francogp/auditor` (consumer applications and standalone package distributions alike), the `"build"` script in `package.json` MUST be chained with a prior invocation of the full auditor (e.g., `"build": "auditor && vite build"`, `"build": "npm run audit && vite build"`, or `"build": "npm run audit && tsc -p tsconfig.build.json && node --experimental-strip-types src/cli/make_executable.ts && npm run audit:build"`). Bypassing build chaining is permitted only via explicit configuration (`config.packageScripts.enforceBuildAudit: false`). `validate_audit_config` provides auto-repair (`--fix`) to automatically chain `auditor &&` into the build script and populate missing essential auditor scripts from `recommended_package_scripts_template.json`.

- **Ambiguous Re-Export Prohibition (TS2308)**: When sharing constants across core modules (e.g. `auditConfig.ts` and `auditContract.ts`) that are both re-exported via `export *` in `src/index.ts`, the constant MUST be exported canonically from a single module and imported without re-exporting in peer modules to prevent ambiguous export collisions.
