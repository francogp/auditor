# SCSS / CSS to GSAP Migration & Performance Guide

Comprehensive reference of SCSS, CSS, and imperative DOM animation patterns that can be translated to **GSAP** for 60fps GPU-composited performance, batched DOM reads/writes (zero layout thrashing), deterministic playback control, and automatic lifecycle/accessibility cleanup.

Derived systematically from the official GSAP skills (`gsap-core`, `gsap-performance`, `gsap-timeline`, `gsap-scrolltrigger`, `gsap-plugins`, `gsap-frameworks`, `gsap-utils`) and `scss-best-practices`.

## Complete Translation Table (SCSS / CSS / DOM → GSAP)

| Case                                                                             | SCSS / CSS / DOM Example                                                                                                | GSAP Equivalent                                                                                                                                                | Primary Benefit                                                                                                      |
| :------------------------------------------------------------------------------- | :---------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------- |
| **1. Generic `transition: all`**                                                 | `.card { transition: all 0.3s ease; }`                                                                                  | Remove `transition: all`; animate explicitly: `gsap.to('.card', { y: -4, duration: 0.3, ease: 'power2.out' })`                                                 | Eliminates accidental layout-property interpolation and prevents CSS ↔ GSAP ticker fighting                          |
| **2. Layout properties (`top`, `left`, `width`, `height`, `margin`, `padding`)** | `.box:hover { left: 40px; width: 220px; transition: left 0.3s, width 0.3s; }`                                           | `gsap.to('.box', { x: 40, scaleX: 1.1, duration: 0.3, ease: 'power2.out' })`                                                                                   | Moves work from CPU Layout/Reflow to GPU Compositor (`transform`)                                                    |
| **3. Raw `transform` strings**                                                   | `.card { transition: transform 0.3s; } .card.is-open { transform: translateX(20px) scale(1.05) rotate(5deg); }`         | `gsap.to('.card', { x: 20, scale: 1.05, rotation: 5, duration: 0.3 })`                                                                                         | Independent transform aliases apply in deterministic order (`translate -> scale -> rotate`) and avoid string parsing |
| **4. `transform: ... !important` centering**                                     | `.modal { top: 50%; left: 50%; transform: translate(-50%, -50%) !important; }`                                          | Center via Flexbox/Grid in SCSS; animate `x`, `y`, `scale` via GSAP (or `xPercent: -50, yPercent: -50`)                                                        | `!important` overrides GSAP inline styles and freezes tweens; Flexbox/Grid avoids transform collisions               |
| **5. Fade with `opacity` + `pointer-events`**                                    | `.modal { opacity: 0; visibility: hidden; transition: opacity 0.2s; } .modal.open { opacity: 1; visibility: visible; }` | `gsap.to('.modal', { autoAlpha: 1, duration: 0.2 })` / `gsap.to('.modal', { autoAlpha: 0, duration: 0.2 })`                                                    | `autoAlpha` automatically toggles `visibility: hidden` at `0` so invisible elements never block clicks               |
| **6. Multi-step `@keyframes` / `animation-delay` chains**                        | `.a { animation: in 0.4s forwards; } .b { animation: in 0.4s 0.4s forwards; }`                                          | `gsap.timeline({ defaults: { duration: 0.4, ease: 'power2.out' } }).from('.a', { y: 16, autoAlpha: 0 }).from('.b', { y: 16, autoAlpha: 0 })`                   | Runtime control (`play`, `pause`, `reverse`, `seek`, `kill`) and exact relative timing (`<`, `+=0.2`, labels)        |
| **7. Manual `@for` / `:nth-child` stagger delays**                               | `@for $i from 1 through 10 { .item:nth-child(#{$i}) { transition-delay: #{$i * 0.05}s; } }`                             | `gsap.from('.item', { y: 20, autoAlpha: 0, stagger: 0.05 })` (or `{ amount: 0.4, from: 'center' }`)                                                            | Eliminates bloated CSS rule generation and batches all elements in a single GSAP pass                                |
| **8. Grid / non-linear element distribution**                                    | Complex `:nth-child` delay formulas per column/row                                                                      | `gsap.to('.cell', { scale: gsap.utils.distribute({ base: 0.5, amount: 0.5, from: 'center', grid: 'auto' }) })`                                                 | Built-in 2D grid and eased distribution without brittle CSS math                                                     |
| **9. Expand / collapse (`max-height: 0 -> auto`) & layout reordering**           | `.panel { max-height: 0; overflow: hidden; transition: max-height 0.3s ease; }`                                         | `const state = Flip.getState('.panel'); /* toggle class */ Flip.from(state, { duration: 0.3, ease: 'power2.inOut' });`                                         | Smooth 60fps FLIP (`transform`) animation for true `auto` dimensions and DOM reordering                              |
| **10. Scroll reveal (`IntersectionObserver` + CSS transitions)**                 | `.reveal { opacity: 0; transform: translateY(24px); transition: 0.5s; }` + `IntersectionObserver`                       | `ScrollTrigger.batch('.reveal', { onEnter: (els) => gsap.to(els, { autoAlpha: 1, y: 0, stagger: 0.1 }) })`                                                     | Native rAF batching, automatic resize/refresh handling, and clean teardown via `ScrollTrigger`                       |
| **11. Scroll-linked progress / parallax / pinned sections**                      | `window.addEventListener('scroll', ...)` mutating CSS `--scroll` or `top`                                               | `gsap.to('.el', { x: 200, scrollTrigger: { trigger: '.section', start: 'top top', end: '+=1000', pin: true, scrub: 1 } })`                                     | Avoids scroll-event layout thrashing; `scrub` & `pin` keep progress synced on compositor                             |
| **12. Fake horizontal scroll inside vertical page**                              | Nested `scroll` listeners translating horizontal wrappers                                                               | `const tween = gsap.to('.track', { xPercent: -100, ease: 'none', scrollTrigger: { trigger: '.wrap', pin: true, scrub: true } })` + `containerAnimation: tween` | Deterministic 1:1 vertical-to-horizontal scroll mapping (`ease: 'none'`)                                             |
| **13. Smooth scroll to anchor / container**                                      | `html { scroll-behavior: smooth; }` or `el.scrollIntoView({ behavior: 'smooth' })`                                      | `gsap.to(window, { duration: 0.8, scrollTo: { y: '#section', offsetY: 60 }, ease: 'power2.inOut' })`                                                           | Consistent cross-browser easing, interruptible on user scroll, supports `offsetY`                                    |
| **14. High-frequency `mousemove` CSS vars / `left` updates**                     | `el.addEventListener('mousemove', (e) => { el.style.setProperty('--x', e.clientX + 'px'); })`                           | `const xTo = gsap.quickTo('.follower', 'x', { duration: 0.4, ease: 'power3' }); /* on mousemove: xTo(e.pageX) */`                                              | Reuses a single tween instance without allocating new tweens or CSS var style recalcs per frame                      |
| **15. Drag / swipe with pointer listeners & CSS `touch-action`**                 | Manual `pointerdown`/`pointermove` mutating `transform`                                                                 | `Draggable.create('.card', { type: 'x,y', bounds: '#wrap', inertia: true })` or `Observer.create({ ... })`                                                     | Unified mouse/touch/wheel normalization with optional `InertiaPlugin` momentum                                       |
| **16. SVG stroke drawing (`stroke-dashoffset`)**                                 | `.path { stroke-dasharray: 500; animation: draw 1s linear forwards; }`                                                  | `gsap.from('.path', { drawSVG: 0, duration: 1, ease: 'none' })`                                                                                                | Computes exact SVG path length automatically across viewBoxes and browsers                                           |
| **17. Per-character / per-line CSS animation delays**                            | Manually splitting text into `<span>`s with inline `--i` delay vars                                                     | `SplitText.create('.title', { type: 'lines,words', autoSplit: true, onSplit: (self) => gsap.from(self.lines, { y: 40, autoAlpha: 0, stagger: 0.05 }) })`       | Automatic `aria-label` accessibility, font-load re-splitting (`autoSplit`), and `.revert()` cleanup                  |
| **18. `will-change` on `*` or inside `@keyframes`**                              | `* { will-change: transform, opacity; }` or `@keyframes pulse { 0% { will-change: transform; } }`                       | Apply `will-change: transform` statically only on active animated nodes (or let GSAP manage runtime layers)                                                    | Prevents GPU VRAM exhaustion and layer thrashing                                                                     |
| **19. Responsive breakpoints & `@media (prefers-reduced-motion)`**               | Duplicated CSS animations across `@media` queries and reduced-motion overrides                                          | `const mm = gsap.matchMedia(); mm.add({ desktop: '(min-width: 800px)', reduce: '(prefers-reduced-motion: reduce)' }, (ctx) => { ... })`                        | Automatically reverts tweens & ScrollTriggers on media change and honors vestibular safety (`duration: 0`)           |
| **20. Component mount/unmount cleanup & scoped selectors**                       | Global class toggles left active after SPA route change                                                                 | `const ctx = gsap.context(() => { ... }, rootEl);` + `onUnmounted(() => ctx?.revert())`                                                                        | Scopes selectors to `rootEl` and kills/reverts all tweens & ScrollTriggers on unmount                                |

## Static Detection Opportunities in `@francogp/auditor`

The following stylesheet patterns from the table above can be detected deterministically via AST in `scssModernAnalyzer.ts` / `validate_scss_architecture.ts` (and Stylelint):

1. **`transition: all` / `transition-property: all`**: Always flaggable as an anti-pattern (especially when `gsap` is declared in `package.json`).
2. **Layout-triggering properties in `transition` or `@keyframes`**: `width`, `height`, `top`, `left`, `right`, `bottom`, `margin*`, `padding*`, `max-height`.
3. **`transform: ... !important`**: Freezes GSAP inline transform tweens.
4. **SCSS `@for` loops emitting `transition-delay` / `animation-delay`**: Candidate for GSAP `stagger`.
5. **`will-change` inside `@keyframes` or `*` selector**: Already partially enforced by `scss-universal-expensive-selectors` (`will-change` on `*`).
