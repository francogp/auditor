# Purpose

Command-line interfaces, orchestrators, and developer reporting tools for `@francogp/auditor`. Provides the full audit runner (`audit_full.ts`) with its built-in warning ratchet (`auditRatchet.ts`), production bundle visualizer analyzer (`audit_bundle.ts`), findings query reporters, and environment setup scripts.

## Ownership

Architecture & Tooling Engineers.

## Local Contracts

- **Configuration Pre-Flight Validation**: All CLI orchestrators (`audit_full.ts`, `audit_bundle.ts`) MUST execute `assertAuditConfigComplete(config)` immediately after loading `audit.config.ts`, failing fast with exit code 1 if any mandatory subsystem is omitted.
- **Streaming Execution & Universal Sub-Auditor Disclosure**: The master orchestrator streams step-by-step progress and sub-auditor breakdown results for all suites via `BaseAuditor` / `ICompositeAuditor`, formatting live badges cleanly (silent when 0 findings, `[🐛 ${count}]` when findings > 0) and writing full structured output to `scratch/audits/latest_audit.json`.
- **Capability-Driven Auto-Repair & Zero Partial Conclusions Mandate (`--fix` / `fix`, `speed=light|heavy|full`, `only-speed=light|heavy|full`)**: When invoked with `fix` or `--fix`, the orchestrator (`audit_full.ts`) and scanner (`auditScanner.ts`) dynamically isolate and run only auto-repair suites (`fix: 'priority' | 'normal'`, `capabilities.fix === true`) under a dedicated `[ 🛠️ MODO REPARACIÓN AUTOMÁTICA ]` terminal interface (`fix: 'priority'` executes first). Auto-fix mode MUST NEVER output remaining error/warning counts, findings category tables, or pass/fail verdict banners (`renderConsolidatedFooter`, `printFindingsSummary`), nor direct agents to inspect partial fix reports (`latest_fix_audit.json`). Upon completion of the repair pass, `audit_full.ts` strictly renders `renderAutoFixCompletionBanner`, instructing developers and AI agents to execute the canonical full audit (`npm run auditor`) to inspect findings and continue working, and exits cleanly with code 0. The 3-tier speed engine filters suites by cumulative ceiling (`speed=light|heavy|full`, default `speed=heavy` `🐢`) or exact tier isolation (`only-speed=light|heavy|full`, `🐇`/`🐢`/`🐘`), and dispatches `TieredCommandProfile` (`speed: ['light', 'full']`) suites with their active tier profile.
- **Exit Code Integrity**: Any suite error exits with code 1; passing audits exit with code 0.
- **Warning Ratchet (`auditRatchet.ts`)**: On full default runs (`npm run auditor`, `npm run auditor:full`), `audit_full.ts` fingerprints every warning by content and fails on any fingerprint missing from `.auditor/audit-baseline.json` at `config.ratchet.productionRef` (default `origin/main`). The local baseline only shrinks (auto-rewritten on clean full runs); tampered or missing baselines fail loudly; `--init-baseline` bootstraps it once. Git is invoked with `spawnSync` argument arrays only (no shell interpolation).
- **Bundle Analysis**: `audit_bundle.ts` validates client assets against chunk size budgets and detects duplicate module bloat.
- **Similar-Code Cache Execution & Deployment Environment (`AUDITOR_ENV=production`)**: `audit_full.ts` orchestrates `validate_similar_code` using OS vector caches (`models/`, `vectors/`) and CPU threading. On setup failure, it renders a prominent Box-Drawing warning banner with the manual installation command (`fallow similar-code setup --local --yes`). It supports the universal production environment flag `AUDITOR_ENV=production` (invoked via `npm run build:deploy` / `auditor-build-deploy`) to cleanly omit vector embeddings analysis and test coverage verification in deployment builds, Docker containers, or GitHub Pages without requiring model downloads or test coverage files. There is no CLI flag.
- **Introspection CLI Modes (`--list`, `--info`, `--json`, `--help`)**: `audit_full.ts` supports dynamic discovery flags: `--list` (80-column Box-Drawing overview table), `--list --json` (machine-readable array of `AuditorManifestDTO[]`), `--info=<suiteId>` (inspection card with purpose, capabilities, evaluated rules, and configuration key), and `--help` (interactive manual).
- **Dynamic Thematic Emoji Propagation**: `auditScanner.ts` extracts mandatory `icon` properties directly from sub-auditor classes or instances during auto-discovery, ensuring every task in the streaming runner displays its dedicated visual symbol.
- **Transparent Skip Rendering (`⏭️  SKIP`)**: `audit_full.ts` detects bypassed or skipped suites, clears default rule descriptions, and streams `⏭️  SKIP` in cyan with skip reasons rather than falsely reporting passed status.
- **CLI Flag Precedence & Loud Argument Validation (`bump_version.ts`)**: State-mutating CLI commands MUST intercept `--help` and `-h` flags before parsing positional arguments or executing mutations. Positional parameters and type arguments MUST be strictly validated against the finite domain using O(1) Set membership (`CLI_BUMP_TYPES`: `major`, `minor`, `patch`, `build`, `auto`), failing loudly with exit code 1 on unknown arguments and strictly banning silent fallback to defaults.
- **Dynamic Task Metadata Resolution (`auditTaskFactory.ts`)**: Task creation extracts mandatory `configKey`, `defaultConfig`, and `criticalConfig` directly from auditor instances or manifests, ensuring downstream execution engines and scaffolding routines have zero hardcoded knowledge of specific suite options.
- **Post-Build Compiled Artifact Partitioning (`audit_post_build.ts`, `phase=post-build`)**: Default pre-build audit runs exclude suites with `phase: 'post-build'` (`capabilities.phase === 'post-build'`: `validate_bundle_budget`), routing them to `audit_post_build.ts` (`npm run auditor:post-build` / `auditor-post-build` / `auditor phase=post-build`) to execute post-build against `dist/`.
- **Dynamic Configuration Scaffolding (`auditor fix`)**: When repairing or generating `.auditor/audit.config.ts`, `audit_full.ts` dynamically collects `task.defaultConfig` from all discovered tasks across the repository via `collectConfigSectionsFromTasks`, eliminating hardcoded configuration block lists.
- **Remote Project Execution & Early Chdir Bootstrap (`bootstrapCliProject`)**: All CLI entrypoints (`audit_full.ts`, `report_findings.ts`, `report_fallow.ts`, `report_complexity.ts`, `report_similar_code.ts`, `update_package.ts`, `sync_env_scripts.ts`) MUST invoke `bootstrapCliProject()` before loading configurations or discovering tasks. When targeting an external project via `--project=<path>`, `project=<path>`, `-p <path>`, or `-p=<path>`, it validates the target directory and `package.json` using native Node.js APIs, sets `AUDITOR_HOME_DIR` and `AUDIT_PROJECT_ROOT`, and switches `process.cwd(targetDir)`. `stripProjectCliArgs` cleans project arguments from `process.argv` to prevent downstream argument parser collisions.
- **Robust SemVer Release Tag Resolution & Package Updater Contract (`update_package.ts`, `auditor:update`)**: `auditor-update` updates `@francogp/auditor` across consumer host projects by dynamically discovering remote Git tags via `git ls-remote --tags` (or accepting an explicit target version from CLI args such as `npm run auditor:update -- v9.0.0`). The updater MUST parse SemVer tags using strict numerical component extraction (`parseTagSemver`) and sort them in descending SemVer order (`compareTagsDescending`, `extractTagsFromLsRemote`), cleanly stripping peeled annotated tag markers (`^{}`) and supporting both clean release tags (`vX.Y.Z`) and build-metadata tags (`vX.Y.Z-build...`) with deterministic preference for clean stable release tags over build-suffixed tags. Using naive, fragile regular expressions (`/refs\/tags\/(v\d+\.\d+\.\d+)$/`) that fail on annotated refs or build metadata, or falling back to hardcoded legacy versions upon network failure, is STRICTLY PROHIBITED. In offline environments or unexpected remote failures, the updater MUST dynamically fall back to the project's active `AUDITOR_VERSION`. It executes `preSyncHostPackageJson()` before spawning `npm install`, pre-elevating `vite-plus` to `^1.4.0`, purging redundant direct `vite` dependencies, and ensuring `citty@^0.2.2` in `devDependencies` to prevent npm `ERESOLVE` failures. It strictly installs the auditor as a development dependency (`devDependencies`) with a deterministic pinned tag (`github:francogp/auditor#vX.Y.Z`), updates `package-lock.json`, synchronizes Antigravity agent skills in `.agents/skills/`, synchronizes setup scripts (`setup-windows.ps1`, `setup-linux.sh`), and runs `auditor fix`.
- **Canonical Environment Scripts Synchronization & 7-Bit ASCII Purity Contract (`sync_env_scripts.ts`, `auditor:sync-env`)**: Synchronizes canonical `setup-windows.ps1`, `setup-linux.sh`, `update-windows.ps1`, and `update-linux.sh` into host projects. All synchronized setup scripts, update runners, and plugin samples MUST maintain strict 7-bit ASCII purity (bytes `0x00 - 0x7F`) with zero emojis or multibyte UTF-8 characters, preventing silent syntax parsing aborts in Windows PowerShell 5.1 (`powershell.exe`) caused by Windows-1252 ANSI byte collisions (such as byte 0x93 of `✓` parsed as an opening smart quote `“`).
- **Mandatory Library Minimums CLI Inspector Contract (`auditor-dependencies`, `report_dependencies.ts`)**: The CLI binary `auditor-dependencies` (also accessible via `npm run auditor:dependencies` and early command `auditor dependencies` / `auditor deps`) inspects, evaluates, and reports the status of mandatory minimum library versions governed by `@francogp/auditor` against the target host project's `package.json` and `package-lock.json`. It operates hermetically without loading auditor suites or executing host extensions, rendering Box-Drawing tables (`unifiedTheme`), structured JSON (`--json`), and grouped install commands (`--commands`). AI agents and developers are strictly prohibited from executing ad-hoc `node -e` scripts or manual `npm view` queries on host dependencies.
- **Native Audit Inspection Suite & Zero Ad-Hoc Scripts Mandate (`report_findings.ts`, `auditor:rules`, `auditor:by-rule`, `auditor:next`)**: Developers and AI agents are strictly prohibited from creating, running, or recommending ad-hoc scratch scripts (`analyze_*.ts`, `summarize_*.ts`, `node -e`) to parse or filter `scratch/audits/latest_audit.json`. The framework provides canonical, first-class inspection tools: (1) `auditor:next` / `npm run auditor:next` (or `phase=next`) automatically isolates findings to the earliest active strategic phase (`setup` -> `prune` -> `dedup` -> `contracts` -> `behavior` -> `hygiene` -> `polish`), postponing downstream errors to eradicate induced false positives; (2) `auditor:rules` / `auditor:by-rule` / `npm run auditor:rules` renders a categorized Box-Drawing table breaking down findings per rule with a consolidated total footer row; (3) `rule=<id>` / `r=<id>` / `ruleId=<id>` filters findings in `report_findings.ts` by exact rule identifier; (4) `flat` / `--flat` / `raw` emits un-truncated single-line finding dumps (`file:line [ruleId] message`) for complete terminal visibility; (5) `file=a,b` supports comma-separated multi-file path matching; and (6) partial run resilience ensures inspecting findings from partial audits (`speed=light`, `family=architecture`) renders non-blocking terminal notices instead of failing.
- **AI-Friendly Compact Console Mode & Interactive Human Mode (`consoleMode: 'compact' | 'human'`)**: All audit executions and CLI reporters default to AI-friendly compact mode (emitting clean 3-line English status blocks or bracketed token lines). The full interactive Box-Drawing output with live telemetry (`🔍 [X/Y]`) and summary tables is rendered on demand via `human`, `format=human`, `--human`, or dedicated package scripts (`npm run auditor:human`, `npm run auditor:lint:human`, `npm run auditor:full:human`, `npm run auditor:findings:human`, `npm run auditor:next:human`). In AI compact mode, all CLI reporters MUST strictly omit loose decorative emojis (`✨`, `🔒`, `🔍`, etc.) and standardize on uppercase ASCII bracketed tokens (`[OK]`, `[FOCUS]`, `[Notice]`, `[FAIL]`, `[Errors]`, `[Warnings]`). In human mode, reporters MUST frame cards, banners, and status verdicts using `UnifiedTheme` Box-Drawing (`buildNoticeBox`, `renderBanner`, `boxen`, `cli-table3`) with semantic double borders, uppercase titles, and dynamic terminal width calculation. Master orchestrator invocations cleanly silence Node intrinsic permission warnings (`PERM0002`) via `--disable-warning=PERM0002`.
