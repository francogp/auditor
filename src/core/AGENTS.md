# Purpose

Core runtime foundations of `@francogp/auditor`. Provides the base auditor OOP hierarchy (`BaseAuditor`, `FileScanAuditor`), contract types, configuration loading (`audit.config.ts`), terminal Box-Drawing rendering (`unifiedTheme`), shared AST parsing context, streaming execution runners, and filesystem permission guards.

## Ownership

Architecture & Tooling Engineers.

## Local Contracts

- **Base Class Inheritance**: All sub-auditors across the system must inherit from `BaseAuditor` or `FileScanAuditor`.
- **Canonical Ignore Registry & Universal Ignores Contract (`canonicalIgnoreRegistry.ts`, `ALWAYS_IGNORE_DIRS`, `cachePaths`)**: Single source of truth for repository ignores. `ALWAYS_IGNORE_DIRS` contains strictly the universal infrastructure, VCS, temporary, workspace, and auditor configuration directories (`.git`, `node_modules`, `scratch`, `tmp`, `volumes`, `.vscode`, `.github`, `.gemini`, `.auditor`). Sub-auditor tool caches outside scratch (`.fallow`, `.oxlintcache`, `.stylelintcache`) are declared by each suite via `cachePaths: readonly string[]` and registered dynamically via `registerDynamicCachePath`. Specific subsystem ignores (`subsystem.ignoreGlobs`, e.g. `dox.ignoreGlobs`) isolate exclusions to that specific sub-auditor without leaking across other suites.
- **Strict Subsystem Ignore Isolation, Zero Hardcoded Ignores & Sovereign Configuration Mandate (`canonicalIgnoreRegistry.ts`, `vitePlusConfigSync.ts`)**: Every sub-auditor, code scanner, and satellite tool configuration strictly encapsulates its own ignore rules. Sub-auditors are fully sovereign and PERMITTED to configure their own ignores voluntarily if desired (e.g. `paths.ignoreGlobs`, `oxlint.ignoreGlobs`). However, HARDCODING IGNORES IN SOURCE CODE OR CROSS-POLLUTING IGNORES ACROSS SUBAUDITORS IS CATEGORICALLY PROHIBITED. Under NO circumstances may an individual sub-auditor's configuration or target directories (including `paths.dataRoots`, `paths.demoRoots`, `paths.testRoots`, `paths.e2eRoots`, `coverage.exemptGlobs`, or legacy ESLint scrapings) be injected uninvited into another tool's ignores or into `lint.ignorePatterns` of `vite.config.ts`. The ONLY ignore patterns that may be injected globally into satellite tools are `paths.ignoreGlobs` (and direct `paths` variants: `ignoredDirs`, `ignoredPatterns`, `exemptFiles`) alongside `CANONICAL_SYSTEM_IGNORE_GLOBS` from `src/core/canonicalIgnoreRegistry.ts`.
- **Mandatory Default Auditing for `vite.plugins.ts` (`viteConfigAst.ts`, `vitePlusConfigSync.ts`)**: `vite.plugins.ts` is the developer-owned application module housing modular Vite plugins. `vite.plugins.ts` MUST ALWAYS BE AUDITED, LINTED, AND FORMATTED BY DEFAULT across all static analyzers and sub-auditors (`validate_oxlint`, `validate_oxfmt`, `validate_similar_code`, etc.). Placing `vite.plugins.ts` in any default ignore list or ignoring it without explicit developer instruction is strictly prohibited.
- **Auditor AST Automated Strong Typing on Governed Satellite Configs (`viteConfigAst.ts`, `synchronizeViteConfigAst`, `applyViteConfigAstTransformations`)**: Since `vite.config.ts` is an auditor-owned satellite configuration generated and synchronized by `@francogp/auditor`, the AST transformer engine is strictly responsible for automatically constructing and injecting explicit TypeScript return types on all standard Vite/Rollup functions, methods, and expressions (`onwarn(warning, warn): void`, `bypass: (req): string | undefined =>`, `manualChunks(id): string | undefined`, `outExtensions: (): { js: string; dts: string } =>`). This guarantees 100% compliance with strict Java-style typing (`typescript/explicit-function-return-type` with all exemptions disabled) across all host projects without manual developer intervention.
- **BaseEntityRegistry Architecture & SSoT Protocol (`baseRegistry.ts`, Strict Interfaces, Zero Shims)**: Generic typed in-memory entity registry base class implementing `IBaseEntityRegistry<TItem>` and providing `register`, `registerMany`, `get`, `getAll`, `has`, `delete`, `reset`, `size`, `dispose()`, and static `BaseEntityRegistry.unregister(registry)`. Inherited uniformly by `GitIgnoreRegistry`, `PackageScriptRegistry`, `ConfigFileRegistry`, and `SuiteIgnoreRegistry`. All registries are protected via 3-layer interface typing (compile-time exact type invariance assertions, public interface masking, and runtime prototype introspection canaries). All legacy alias methods (`count()`, `getRequirements()`, `unregister(id)`, `clear()`) are permanently eradicated across the codebase.
- **Path Exemption SSoT & Proxy Re-Export Eradication (`reportUtils.ts`, `isPathExempt`)**: Path exemption evaluation resides strictly in `reportUtils.ts` (`isPathExempt(filePath, config)`). Proxy re-exports of `isPathExempt` or `CANONICAL_IGNORE_DIRS` across intermediate core or suite files are strictly prohibited; consumers import directly from their canonical SSoT module.
- **Pruning-at-Traversal-Level Mandate & Documentation GitIgnore Isolation (`collectRepositoryFiles`, `collectDocumentationFiles`)**: All ignored directories (`ALWAYS_IGNORE_DIRS`, dynamic tool caches, and `paths.ignoredDirs`) MUST be evaluated and pruned at the filesystem walker level (`walkRepositoryFiles`) during directory traversal. For Markdown (`.md`) scans in `family: 'documentation'` suites (`setupAuditor.collectFiles`) and `collectDocumentationFiles`, `.gitignore` rules are additionally evaluated and pruned at the traversal level via `GitIgnoreMatcher` while honoring single- or multi-segment `unignoreDirs` (both nested segment matches and `isPathContained`), leaving source-code comment scans and non-documentation families isolated. Sub-auditors and analyzers (including `doxAnalyzer`) are STRICTLY PROHIBITED from performing iterative post-hoc string comparisons (`relPath !== '.auditor'`, `relPath.startsWith(...)`) or ad-hoc exclusions over collected file arrays to filter out ignored trees.
- **Auditor Manifest DTO Contract (`toManifest`, `AuditorManifestDTO`)**: `BaseAuditor` exposes `toManifest(): AuditorManifestDTO` which packages `id`, `name`, `family`, `icon`, `description`, `capabilities`, `rules`, and optional `configKey` into an immutable DTO for AI agents and external tools. Sub-auditors must maintain clean, concise descriptions (`<= 60` chars) and omit redundant configuration summaries.
- **Universal Sub-Auditor Progress Contract & Description Standardization (`ICompositeAuditor`)**: All sub-auditors must declare or dynamically infer their sub-auditor checks via `ICompositeAuditor.getSubAuditors()`. `AuditorOptions` requires mandatory `packageName: string` and `ruleDescriptions: Record<TRuleId, string>` for all declared rules. Descriptions are composed strictly as `${packageName}: ${ruleDescription}`, enforced to `<= 50` characters (`MAX_AUDITOR_DESCRIPTION_LENGTH = 50`) without newlines, throwing an explicit runtime `Error` upon violation. Live step progress renders clean output (silent when 0 findings, formatted count badge via `formatFindingCountBadge` displaying `(<N> errors)`, `(<N> warnings)`, or `(<N> errors, <M> warnings)` when findings > 0) and records findings into `StandardAuditResult.subAuditors` via `ensureSubAuditorsLogged()`.
- **Streaming Console Output Dual Standard & Zero-Nesting Compact Mandate (`TaskStreamCoordinator`, `streamingRunner.ts`)**: Streaming task execution enforces a strict behavioral dichotomy between machine/AI and human interactive modes:
  1. **Compact Mode (`compact`, default)**: Clean suites emitting 0 errors and 0 warnings (or skipped) emit **zero lines** (absolute terminal silence). Suites encountering errors or warnings emit **strictly one single flat line** (`❌ <TaskName> (<taskId>) (<N> errors) <duration>`, `⚠️ <TaskName> (<taskId>) (<N> warnings) <duration>`, or `❌ <TaskName> (<taskId>) (<N> errors, <M> warnings) <duration>`). Emitting nested, indented, or repeated sub-rule lines underneath a suite line in compact mode is strictly prohibited.
  2. **Interactive Human Mode (`human`, `--human`, `AUDITOR_CONSOLE_MODE=human`)**: Renders full Box-Drawing trees (`│`), progress percentages (`[01/77 │ 1%]`), task icons, and all evaluated sub-auditor steps (`🔍` for OK, `❌` for error, `⚠️` for warning).
- **Categorical Prohibition of String Sniffing for Severity & Telemetry**: Deducing rule severity, failure status, or terminal colors via string pattern matching (e.g. `.includes('🐛')`, `.includes('❌')`, `.includes('failed')`) is strictly and categorically prohibited across all runners, coordinators, and loggers. Severity, status badges, and color tokens must be resolved exclusively via typed contract fields (`status: 'passed' | 'warning' | 'failed'`, `errorsCount`, `warningsCount`).
- **Hierarchical Path Containment in Config Ratchet & Anti-Tamper Precision (`isPathCoveredByOnlineExemptions`, `configRatchet.ts`, `transcriptAuthorizationVerifier.ts`)**: When ratcheting path-based exemption fields (`paths.dataRoots`, `paths.exemptGlobs`), the ratchet evaluates spatial path containment via `isPathContained` from native `node:path` / `safePath.ts`. Narrowing an exemption from a parent directory to a more restrictive subdirectory ($E_{\text{local}} \subseteq E_{\text{online}}$) constitutes a legitimate architectural tightening and MUST NEVER trigger a forbidden relaxation (`RELAX`) violation. For discrete (non-path) exemption collections (`ignoreDependencies`, `exemptDependencies`, `ignoreBinaries`, `exemptSignatures`, `exemptCollections`), exact string set subset containment ($S_{\text{local}} \subseteq S_{\text{online}}$) is strictly enforced via `DISCRETE_EXEMPTION_FIELDS`. Anti-tamper verification in `transcriptAuthorizationVerifier.ts` strictly limits mutation checks to files targeting `transcript.jsonl` / `transcript_full.jsonl`. To prevent false positives during legitimate transcript reading, shell inspection distinguishes shell redirections (`(?<![=>-])(?:>>?|1>|2>)\s*[^|&;"'\r\n]*transcript`) from JavaScript syntax operators (`=>`, `>=`) in `node -e` scripts, restricts shell write/delete cmdlets to command or pipeline boundaries (`(?:^|[;&|\r\n])\s*<cmd>`), and asserts that script file writes target transcript as a direct function call argument (`\b(?:writefile|appendfile|createwritestream)\s*\([^)]*transcript`), completely eliminating false tampering flags during background transcript inspection.
- **Mandatory Third-Party Tool Satellite Config Explanation Contract (`explainSatelliteConfig`, `BaseAuditor`, `auditorContractConformance.ts`)**: Every sub-auditor and host extension declaring `usesThirdPartyTool: true` MUST declare `explainSatelliteConfig` in its constructor `thirdPartyToolPolicy` ({ `configFile`, `ssotKey`, `undeclaredEntryRuleId`, `configSuiteId` }), or declare `explainSatelliteConfig: undefined` explicitly if the tool requires no external configuration file (e.g. `npm audit`). If omitted, `BaseAuditor` and `auditorContractConformance` fail loudly during instantiation (`throw new Error(...)`), preventing third-party tool registration without configuration governance. Subclasses expose this via `auditor.explainSatelliteConfig()`.
- **Universal Empirical Individual Timing Mandate**: Multi-rule sub-auditors and host extensions MUST record and display real empirical execution runtime badges (`(X ms)` or `(<0,1 ms)`) for 100% of their declared rules. Synthetically dividing execution times or duplicating batch durations across rules is strictly prohibited. Each rule check must be measured individually via superclass wrappers (`this.runSubAuditorSync<T>(ruleId, () => ...)`, `await this.runSubAuditor<T>(ruleId, async () => ...)`, or `declareFileSubAuditor(ruleId, handler)`). Because these wrappers invoke `this.markRuleEvaluated(ruleId)` internally, preceding them with explicit `markRuleEvaluated` calls is prohibited as redundant boilerplate. Legacy batch execution wrappers (`runSubAuditorsBatch`, `runSubAuditorsBatchSync`) are permanently eradicated from the codebase under the Zero Backward-Compatibility policy; external monolithic linters (Oxlint, Stylelint, Fallow) deconstruct and report telemetry for each declared rule individually via `this.reportRuleDuration(ruleId, durationMs)`. When a subsystem or directory does not exist or is disabled in config, suites must explicitly call `this.markRuleNotApplicable(ruleId, 'reason')` to prevent false passes with `(0 ms)` badges.
- **Modular Vite Plugin Extraction & Local Helper Pruning Mandate (`extractVitePluginsToModule`, `viteConfigAst.ts`)**: When migrating inline Vite plugins from `vite.config.ts` to `vite.plugins.ts`, the AST transformer MUST automatically extract and relocate local helper function declarations (`isPluginFunctionDeclaration`) and associated variable statements into `vite.plugins.ts`. Simultaneously, it MUST prune the extracted declarations and unused type specifiers (`type Plugin`, `type HmrContext`) from `vite.config.ts` to prevent `eslint(no-unused-vars)` violations, while strictly preserving specifiers referenced elsewhere in `defineConfig`.
- **Orphaned Typechecker Pruning & DevDependencies Auto-Sanitization (`removeLegacyDependencies`, `vitePlusConfigSync.ts`)**: When migrating host repositories to unified Vite+ (`vp check`), the synchronization engine MUST automatically inspect `package.json` scripts and prune deprecated typechecking dependencies (`vue-tsc`) from `devDependencies` if no other package script references or invokes them, eliminating false-positive `fallow-unused-dependencies` violations.
- **Offset-Free Deterministic AST Mutations for Modular Plugins (`updateExistingVitePluginsAst`, `viteConfigAst.ts`)**: Sequential AST mutations on existing source files (such as `vite.plugins.ts`) MUST re-parse the `ts.SourceFile` on every mutation step (`updateVitePlusImportTypes`, `insertMissingPluginImports`, `insertMissingDeclarationsIntoPlugins`, `updatePluginsInitializerAst`) instead of reusing stale character offset integers from prior parses. Reusing stale offsets causes text slicing drift that splices code into the middle of unrelated identifiers or import statements.
- **Non-Destructive Auto-Fix & Tooling Migration Protocol (`vitePlusConfigSync.ts`)**: Auto-fix operations that modernize repository tooling and configurations (such as migrating to Vite+) MUST execute a non-destructive 5-stage sequence: (1) **Extract & Merge**: Parse and extract all existing plugins, custom options, and test suites (`test: { ... }`) from legacy files (`vitest.config.ts`, `vite.config.ts`) and merge them into `vite.config.ts` without losing existing plugins or configurations, (2) **Rewrite Imports**: Rewire testing imports from `'vitest'` to `'vite-plus/test'`, (3) **Runtime Migration**: Migrate `.nvmrc` to `.node-version`, (4) **Package Synchronization**: Inject `'vite-plus'` into `devDependencies`, purge redundant direct `'vitest'` and `'vite'` dependencies in favor of Vite+'s unified toolchain, and remove orphaned `eslint*` dependencies, and (5) **Certified Cleanup**: Purge legacy configuration files (`eslint.config.js`, `vitest.config.ts`, `.nvmrc`, `tsconfig.build.json`) ONLY after stages 1–4 complete with 100% success. In addition, `syncPackageJsonForVitePlus` purges obsolete overrides (`braces`, `micromatch`), keeps security overrides (`js-yaml`, `katex`, `smol-toml`, `stylelint-config-recommended`), and evaluates dependency floors via `semver.minVersion` without forcing exact string overwrites or downgrading host projects that declare newer versions. Purging or overwriting configuration files before successful migration is strictly prohibited.
- **Migration-First, Delete-Last Configuration Sync Gate (`cleanLegacyConfigFiles`, `vitePlusConfigSync.ts`)**: Auto-fix and tooling migration routines that modernize repository configurations to Vite+ are strictly prohibited from deleting legacy configuration files (`vitest.config.ts`, `eslint.config.js`, `tsdown.config.ts`) unless `vite.config.ts` exists on disk and actively contains all equivalent configuration sections (`hasTest`, `hasLint`, and `hasPack`). If any equivalent section is missing or unverified, legacy configuration files MUST be preserved intact to prevent data loss and broken test/lint workflows.
- **Mandatory Constructor Contract, Orthogonal Rule Capabilities & Function Identity Deduplication Mandate (`AuditorRuleCapabilities`, `WorkspaceFileCache`, `scanFilesSinglePass`, Zero Fallbacks, Loud Failure, `Set<Function>`)**: Every single parameter, property, and sub-field in sub-auditor constructors (`BaseAuditor`, `FileScanAuditor`) MUST be explicitly initialized with 100% completeness. Silent defaults, fallback objects, and partial contracts are STRICTLY AND CATEGORICALLY ERADICATED across the framework. Specifically, `AuditorRuleCapabilities` requires orthogonal fields (`speed: 'light' | 'heavy' | 'full' | readonly AuditExecutionSpeed[]`, `phase: 'normal' | 'post-run' | 'post-build'`, `md: boolean`, `ast: boolean`, `changedOnly: boolean`, `critical: boolean`) to be declared explicitly in `ruleCapabilities` across every core suite and host extension, while `fix` is dynamically computed by `BaseAuditor` without manual boolean declarations. Critical suites (`critical: true`) bypass the speed ceiling in `auditor:lint` and `auditor:critical`. Furthermore: (1) If `critical: true` and `speed` declares 2 or more speeds (e.g. `speed: ['light', 'full']`), the engine MUST ALWAYS select the fastest (`light`) when no speed is specified in invocation, ensuring instantaneous incremental/cache runs in direct executions. (2) Inventing or duplicating speed tiers that repeat identical CLI arguments or behaviors is strictly prohibited. (3) In the Full tier (`🐘`), whole-project audit runs without delta clipping, but caching (`--cache`, `cache: true`) is NEVER turned off across any tier. (4) Multi-profile suites implement `TieredCommandProfile` (`speed: ['light', 'full']`) with clean argument composition using shared constants without literal array duplication. (5) Under the Contract-Driven Auto-Fix Protocol, Zero False-Fix Mandate, and Function Identity Deduplication Mandate, suites derive `fixableRuleIds` and `capabilities.fix` strictly from registered executable repair functions in constructor options (`ruleFixers`), configuration files (`configFiles`), or sub-auditors (`declareFileSubAuditor` with `fix`, `declarePatternSubAuditor` with `replace`). If a rule has NO registered mechanical repair algorithm, it is strictly unfixable (`fix: 'none'`, `isFixable = false`), and reporting non-mechanical errors as auto-fixable to users or AI agents is strictly prohibited. When multiple sub-auditors share the exact same `audit` or `fix` function across rules, `FileScanAuditor` executes it strictly ONCE per document (`Set<Function>`); if `audit === fix`, running in `--fix` mode executes it strictly ONCE. In `BaseAuditor.executeRuleFixers`, shared fixer references are tracked via `Set<AnyRuleFixerFn>` and run strictly once per run. Furthermore, `BaseAuditor` provides `WorkspaceFileCache` (`this.getFileLines(file)`, `this.getFileContent(file)`) and `this.scanFilesSinglePass(files, handlers)` to eliminate redundant multi-pass file reads and RAM spikes across rules. Metadata properties `configKey`, `defaultConfig`, and `criticalConfig` (can be empty object `{}`, but never undefined) are strictly mandatory across all suites; task factories and discovery runners MUST throw immediate, loud errors (`throw new Error(...)`) if any suite or extension omits explicit configuration keys, defaults, or critical contracts. When the framework updates, unmigrated extensions or sub-auditors lacking required constructor fields or sub-fields MUST fail loudly and block execution, forcing consumers to update all metadata explicitly.
