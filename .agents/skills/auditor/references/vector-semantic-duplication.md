# Vector Semantic Duplication, Hardware Execution & Cache Architecture

This document specifies the technical design, hardware requirements, cache lifecycle, and operational policies for the Vector Semantic Duplication static analysis engine (`validate_similar_code`) within `@francogp/auditor`.

---

## 1. Architectural Overview & Intent

The vector semantic duplication engine (`validate_similar_code.ts`) verifies semantic code duplicates across TypeScript and Vue files using dense vector embeddings generated by Fallow:

- **Model**: `jina-embeddings-v2-base-code` (8192 token context window, specialized for multi-language code similarity).
- **Sensitivity Threshold**: Strict similarity threshold of `0.95`.
- **Exclusion Policy**: Self-file duplication is excluded by default (`ignoreSameFile: true`) to prevent reporting overloaded functions or internal helper variants.
- **Reporting**: Detected semantic clones are reported as actionable violations (`similar-code-detected`), complete with similarity percentage, source line mappings, and refactoring guidance.

---

## 2. Hardware Execution Architecture (Candle CPU)

Execution of the embedding model runs strictly on **Candle CPU**:

- **Pure CPU Execution**: Operates exclusively in CPU space using native Rust Candle kernels without CUDA, ROCm, or external GPU drivers.
- **Parallel Acceleration**: Multi-threaded execution accelerated via `--threads ${os.availableParallelism()}` leveraging all physical CPU cores.
- **Zero Heavy Toolchains**: Does not require Python, PyTorch, or GPU container runtimes.

---

## 3. OS User Cache Directories & Pre-Creation Invariant

Vector embeddings and model weights are persisted in the operating system's standard user cache directory:

- **Windows**: `%LOCALAPPDATA%\fallow\similar-code`
- **Linux**: `~/.cache/fallow/similar-code`
- **macOS**: `~/Library/Caches/fallow/similar-code`

### Subdirectory Structure & Windows `os error 3` Prevention

The cache directory layout comprises two mandatory subdirectories:

```text
<cache_root>/similar-code/
├── models/   # Downloaded Jina embedding weights and tokenizer configs
└── vectors/  # SQLite or memory-mapped vector cache databases
```

> ⚠️ **CRITICAL WINDOWS INVARIANT**:
> On Windows, Rust's `std::fs` operations will fail loudly with `os error 3` (The system cannot find the path specified) if the parent directory hierarchy does not pre-exist when opening vector cache files.
> The auditor framework (`ensureFallowCacheDirs`) and root setup scripts (`setup-windows.ps1`, `setup-linux.sh`) systematically pre-create both `models/` and `vectors/` subdirectories prior to CLI invocation.

---

## 4. Execution Tiers & Production Deployment Skip Guard

Vector semantic duplication executes in full development and verification passes:

- **Active In**:
  - Master full audit: `npm run auditor`, `npm run auditor:full`
  - Dedicated CLI inspection: `npm run auditor:similar`
- **Automatically Bypassed In**:
  - Fast presets: `speed=light` (`🐇`), `preset=md`
  - Headless production deployments: `AUDITOR_ENV=production`

### Strict Local Execution Mandate

AI agents and developers are **strictly prohibited** from bypassing vector semantic duplication or setting bypass environment variables during local development, interactive agent turns, local builds, or developer test runs.

Leveraging the warm disk cache in `~/.cache/fallow/similar-code`, incremental vector scans complete in approximately **~2 seconds** across thousands of lines of code.

### Headless Production Deployment Guard (`AUDITOR_ENV=production`)

Cleanly skipping development-only suites (including vector semantic duplication `validate_similar_code`, test coverage verification `validate_test_coverage`, and local git configuration `validate_git_config`) is **strictly and exclusively** governed by the universal environment variable `AUDITOR_ENV=production`.

This mode is invoked via `npm run build:deploy` (or CLI `auditor-build-deploy`) and is reserved exclusively for:

1. Docker container builds.
2. Remote deployment scripts.
3. Headless CI/CD publishing runners where local cache directories do not exist.

---

## 5. Companion Model Setup & Resilient Fallback

When executed on a clean machine where model weights have not yet been cached:

1. **Automatic Initialization**: The auditor attempts to download the companion model automatically via:

   ```bash
   fallow similar-code setup --local --yes
   ```

2. **Resilient Non-Fatal Banner**: If automatic network download is blocked (e.g. strict firewall or offline container):
   - The auditor renders an emphatic Box-Drawing warning banner with the manual installation command.
   - It records `fallow-similar-code-failed` as a non-fatal warning (`severity: 'warning'`) so that remaining static analysis suites remain unblocked.

See also the official Fallow documentation: [similar-code-analysis.md](https://git.mitgai.net/fallow-rs/fallow/blob/main/docs/similar-code-analysis.md).
