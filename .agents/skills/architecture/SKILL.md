# Architecture Governance Framework

> "Requirements drive architecture. Simplicity ensures longevity. Contracts prevent decay."

Whenever making architectural decisions, designing subsystems, restructuring modules, planning new features, or diagnosing failures, you **MUST** coordinate and strictly enforce the following **Mandatory Design Pillars** and **Primary Debugging Guide**:

---

## 🏛️ Mandatory Design & Architecture Pillars

Before writing code, defining interfaces, or finalizing system designs, invoke and satisfy the design pillars:

| Pillar | Skill Command | Mandatory Invariant |
| :--- | :--- | :--- |
| **1. Domain Typing** | [`/domain-type-first`](../domain-type-first/SKILL.md) | **Zero loose strings, zero `any`, zero `unknown`**. All finite sets, parameters, states, and IDs must derive from canonical compile-time domain unions. |
| **2. Clean Code** | [`/clean-code`](../clean-code/SKILL.md) | **Single Responsibility & Cognitive Simplicity**. Max cognitive complexity ≤ 20, cyclomatic ≤ 25. Flat logic over deep nesting, early guard clauses. |
| **3. DOX Indexation** | [`/dox-navigator`](../dox-navigator/SKILL.md) | **Single Source of Truth in `AGENTS.md`**. Every new file, directory, and architectural boundary must be indexed in its local DOX hierarchy with relative links. |
| **4. Anti-Overengineering** | [`/ponytail`](../ponytail/SKILL.md) | **Shortest path that actually works (YAGNI & KISS)**. Standard library and native platform APIs before dependencies. One clean function before fifty layers. |
| **5. Static Governance & Tools Priority** | [`/auditor`](../auditor/SKILL.md) | **First Official CLI Tools, Zero Premature Scratch Scripts**. Always use `npm run auditor:findings`, `auditor:rules`, `auditor:dupes`, `auditor:magic`, `auditor:motion`, `auditor:o1`, `auditor:types`, `auditor:domain`. Scratch scripts are strictly a last resort. |
| **6. Code Intelligence & Boundaries** | [`/fallow`](../fallow/SKILL.md) | **Architecture Boundaries & Zero Dead Code**. Circular dependency detection, semantic duplication, complexity hotspots, and blast-radius risk scoring before merging. |

## 🔍 Primary Debugging & Evidence-Based Triage Guide (RED-GREEN First)

Whenever a bug, regression, test failure, runtime crash, or unexpected behavior is detected or reported:

| Discipline | Skill Command | Mandatory Protocol |
| :--- | :--- | :--- |
| **Primary Debug & Triage** | [`/systematic-debugging`](../systematic-debugging/SKILL.md) | **RED-GREEN ante todo (Gate 1 Inviolable)**. ## ⚡ Core Invariants

1. **Decoupled Layers**: UI components must never perform direct I/O, raw file manipulation, or invoke database drivers directly. Logic and services orchestrate computations.
2. **Configuration as SSoT**: File paths, budgets, thresholds, and subsystem flags must resolve strictly and dynamically from the central configuration (`.auditor/audit.config.ts`), never hardcoded.
3. **Fail Loud & Fast**: Invariants and boundary validations must throw explicit, actionable errors (`throw new Error(...)`). Never silently swallow errors, auto-heal corrupt states, or provide runtime fallbacks.
4. **Precision Guarantees**: Arithmetic on sensitive values (currency, timestamps, metric counters) must use exact integer scaling, `BigInt`, or explicit rounding modes.
5. **Dynamic Orchestration & Zero Hardcoding**: Runners, coordinators, and dispatchers must never maintain static lists or hardcoded sequences of tasks, suites, or subsystems. Behavior, execution order, and prioritization must be declared dynamically through constructor metadata (`AuditorRuleCapabilities`, such as `fix: 'priority'`), and resolved dynamically via reflection and AST.
6. **Official Locked Skills Isolation & Zero-Guesswork Update (`skills-lock.json`)**: Official vendor skills tracked in `skills-lock.json` (`gsap-*`, `vitest`, `fallow`, `vue-*`, etc.) are immutable third-party assets. They are strictly ignored during file scanning (`isPathIgnored`), their findings are suppressed (`BaseAuditor`), and filesystem writes are blocked (`safeWriteFile`). AI agents and developers must NEVER inspect, refactor, or edit locked skills during repository maintenance tasks; only custom in-house skills (`architecture`, `auditor`, `safe-commit`, etc.) are subject to codebase governance passes. When asked to update, upgrade, or sync locked skills (*"actualizar skills"*, *"update skills"*), execute the deterministic 4-step protocol (`skills update -p -y` → `git status` → `git diff skills-lock.json` → `vp test tests/locked_skills.test.ts`). For architecture patterns and the complete step-by-step update guide, consult the [Official Locked Skills Guide](./references/skills-lock.md#6-official-locked-skills-update-protocol-step-by-step).
7. **Dynamic Language Governance (Zero Hardcoding)**: The agent MUST dynamically consult `.auditor/audit.config.ts` to determine the configured languages: `config.documentation.chatLanguage` strictly governs interactive chat communication, user interviews, options matrices, and conversational explanations; `config.documentation.language` strictly governs repository files, code comments, documentation, and DOX indices (`AGENTS.md`). Skills and agents MUST NEVER hardcode language names or assume fixed languages. Never conflate or mix chat and file writing languages.
8. **Mandatory Dependency & Skill Synchronization**: Whenever upgrading, bumping, or modifying repository libraries in `package.json` (such as `vite-plus`, `fallow`, `vitest`, `valibot`, `vue`, `gsap`, `playwright`, etc.), developers and AI agents MUST concurrently update any corresponding official agent skills tracked in `skills-lock.json` or packaged agent directives. Upgrading a dependency without synchronizing its associated agent skill leads to documentation drift, obsolete CLI flags, and deprecated pattern guidance. Consult the [Dependency-to-Skill Synchronization Matrix](./references/skills-lock.md#7-mandatory-dependency-to-skill-synchronization-matrix) to look up related skills and update them together.
9. **Official Vite+ (`vite-plus` / `vp`) Packaged Agent Directives**: Officially, the `vite-plus` package ships its own canonical agent specification in `node_modules/vite-plus/AGENTS.md` (along with packaged documentation under `node_modules/vite-plus/docs/` and `https://viteplus.dev/llms-full.txt`), and running `vp config` injects the official Vite+ instructions directly into `AGENTS.md`. Whenever working with Vite+ (`vp` CLI, `vite.config.ts`, `vp check`, `vp lint`, `vp fmt`, `vp test`, `vp pack`, `vp build`, `vp env`, `vp config`, `vp migrate`), agents MUST consult `node_modules/vite-plus/AGENTS.md` and the official Vite+ block in `AGENTS.md` instead of inventing ad-hoc skills or legacy tool configs. Comprehensive CLI commands, tutorial prompts, and safe migration protocols are detailed in [vite-plus-guide.md](../auditor/references/vite-plus-guide.md).
10. **Strict Node.js 26+ Native Standard Library & File Management Mandate**: Developers and AI agents MUST imperatively use Node.js 26+ native standard library modules (`node:path`, `node:fs`, `node:url`, `node:util`, `node:crypto`) for all filesystem, path resolution, URL parsing, and runtime operations, especially when handling files and directories. Inventing fragile homebrew regexes to manipulate paths (`.replace(/\\/g, '/')`, `split('/')`), hardcoded drive prefixes (`C:\\`), manual recursive directory walkers (`walkDir`, custom recursive `readdirSync`), or manual path normalization is STRICTLY PROHIBITED. All path resolutions and directory traversals must strictly rely on native `node:path` methods (`path.resolve()`, `path.relative()`, `path.normalize()`, `path.join()`) and framework canonical utilities (`collectRepositoryFiles`, `safePath`, `assertSafePathComponent`) to guarantee 100% deterministic cross-platform safety across Windows, Linux, and macOS. Detailed specification and migration patterns: [native-nodejs-standard-library.md](./references/native-nodejs-standard-library.md).
11. **Mandatory Official Tools Priority & Zero Premature Scratch Scripts**: Developers and AI agents MUST always inspect, diagnose, and refactor codebase issues using the official CLI tools provided by the framework (`npm run auditor:findings`, `npm run auditor:rules`, `npm run auditor:by-rule`, `npm run auditor:by-file`, `npm run auditor:dupes`, `npm run auditor:magic`, `npm run auditor:motion`, `npm run auditor:o1`, `npm run auditor:types`, `npm run auditor:domain`, `npm run auditor:dependencies`, `npm run auditor:version`, `auditor guide <ruleId>`, `vp check`). Specifically, whenever analyzing, inspecting, or querying `scratch/audits/latest_audit.json` or `latest_audit.json`, developers and AI agents MUST activate `/auditor` and use its canonical tools (`npm run auditor:findings`, `npm run auditor:rules`, `npm run auditor:by-rule`, `npm run auditor:by-file`, `npm run auditor:errors`, `npm run auditor:warnings`, `npm run auditor:summary`, `auditor guide <ruleId>`) to analyze `latest_audit.json`, strictly forbidding manual raw JSON reading, shell greps, or ad-hoc parsing scripts. Writing ad-hoc inspection scripts in `scratch/` or inline `node -e` commands is STRICTLY PROHIBITED when official tools exist. Temporary scratch scripts are permitted ONLY as an exceptional last resort when no official tool covers the diagnostic requirement. To consult tool help via npm, ALWAYS use the `help` subcommand (e.g. `npm run auditor:motion help`, `npm run auditor:types help`, avoiding `--help` trapped by npm); for flags, pass `--` (e.g. `npm run auditor:guide -- <regla>`). NEVER invoke `npx`.
12. **Dependency Immutability & Zero Reverse Engineering Mandate**: AI agents and developers are STRICTLY AND CATEGORICALLY PROHIBITED from modifying, editing, patching, or creating files inside `node_modules/` under ANY circumstances, and from using search tools (`Select-String`, `grep`, `Get-ChildItem`) or opening internal source files inside `node_modules/@francogp/auditor/` to figure out rules, configs, or commands. All commands and rules are 100% documented and discoverable through canonical framework interfaces (`npm run auditor:help`, `npm run auditor:guide -- <ruleId>`, `npm run auditor -- info <suiteId>`, and `npm run auditor:<tool> help`). If a tool exhibits an upstream bug or CLI malfunction, report it directly to the human programmer or run `npm run auditor:update`, NEVER tamper with or reverse-engineer `node_modules/`.
13. **Evidence-Based Debugging & RED-GREEN First Mandate (`systematic-debugging`)**: Whenever a bug, test failure, regression, crash, or unexpected runtime divergence is reported or detected, developers and AI agents MUST trigger and follow [`/systematic-debugging`](../systematic-debugging/SKILL.md). Modifying `src/` or applying speculative patches without first creating an isolated reproduction test in RED (Gate 1 Inviolable) is STRICTLY PROHIBITED. All repairs must strictly adhere to the 4-Phase Reactive Bug Resolution Lifecycle, obey the Dual Consultation Gate, and pass closed-loop regression verification.
14. **Daily Workflow & Static Verification Cadence (Inner Loop vs. Outer Completion Gate)**:
    - **Fast Iterative Inner Loop (`npm run auditor:lint`)**: During day-to-day coding, refactoring, and active development, developers and AI agents MUST frequently execute `npm run auditor:lint`. Note that `npm run auditor:lint` is substantially more comprehensive than a simple toolchain linter (`vp check` only runs oxlint/oxfmt/basic types); `auditor:lint` executes the framework's full suite of 76 lightweight sub-auditors (`speed=light` 🐇) with shared AST caching, evaluating domain types, architecture boundaries, hygiene, security, and critical contracts in milliseconds to catch regressions immediately without waiting for heavy global suites.
    - **General Work-Complete Outer Gate (`npm run auditor`)**: BEFORE declaring any task "trabajo completo" (work complete), presenting finished code to the user, or handing over work, developers and AI agents MUST execute the standard global audit (`npm run auditor`). It verifies all applicable suites, enforces the warning ratchet (0 errors, 0 new warnings against `origin/main`), and guarantees codebase integrity across architectural boundaries.
    - **Exhaustive Build & Release Gate (`npm run auditor:full` / `npm run build`)**: Reserved for `/safe-commit`, pre-commit verification, packaging, and CI/CD pipelines (`speed=full` `🐘` with type-aware dead-code, vector duplication, and post-build artifact validation).
15. **Skill Frontmatter YAML Format Mandate & Antigravity Compatibility**: All agent skills under `.agents/skills/*/SKILL.md` MUST define their `description` using folded block scalar syntax (`description: >-`) with 2-space indentation. Unquoted single-line descriptions containing colons followed by spaces (`': '`) or exclamation marks (`!`) break strict Go YAML parsers (causing `mapping values are not allowed in this context` or unrecognized tag failures in Antigravity). Enforced automatically by `validate_agent_plugin` and `tests/skills_conformance.test.ts`.
16. **Canonical CLI Contracts & Citty Governance Mandate (`validate_cli_contracts`, `citty@^0.2.2`)**: All standalone CLI executables, refactoring tools, sub-auditors, and reporting scripts (`src/cli/*.ts`, host scripts, and sub-auditor CLI entrypoints) MUST standardize strictly and exclusively on **`citty`** (`citty@^0.2.2`) via `src/core/cli/cittyHarness.ts` (`defineCommand`, `runMain`, `runCommand`, `COMMON_CLI_ARGS`, `createRefactorCli`, `parseCittyArgs`). Direct, bracketed, or destructured access to `process.argv` (`Deno.args`, `Bun.argv`), `node:util.parseArgs`, homebrew flag parsing (`arg.startsWith('--')`, `.includes('--human')`), and unauthorized third-party argument parsers (`yargs`, `commander`, `minimist`, `cac`, `arg`, `mri`) are strictly prohibited across all repositories and sub-auditors. All command arguments and subcommands must be declaratively declared with typed definitions, and positional tokens without leading hyphens (`human`, `key=val`) must be normalized automatically through `getProcessCliArgs()`. Furthermore, all host projects consuming `@francogp/auditor` MUST declare `"citty": "^0.2.2"` in their `devDependencies`, enforced deterministically in `phase: 'setup'` by `validate_cli_contracts`.
